# 01 서비스 정의

## 1. 어떤 서비스인가

로또 번호를 추천받고, 추천받은 번호와 직접 산 번호를 회차별로 관리하고, 당첨 결과를 확인하거나 알림으로 받는 서비스다. 관리자는 서비스 이용 현황을 보고, 추천 번호가 실제로 어떤 결과를 냈는지 검증한다. 실제 운영을 목표로 한다.

사용자가 얻는 것:

- 번호를 고르기 어려울 때 간편하게 추천받는다.
- 추천 번호와 구매 번호를 한곳에서 관리한다.
- 결과를 직접 확인하거나 알림톡으로 받는다.

추천은 당첨 확률을 높이지 않는다. 모든 조합의 당첨 확률은 같다. 화면과 알림에서 확률이 높아진다고 표현하지 않는다.

## 2. 이용자

| 이용자 | 할 수 있는 일 (첫 출시) |
|---|---|
| 비회원 | 번호 추천, 보존 중인 본인 추천 조회, 즉시 당첨 확인(직접 입력, QR). 외부 알림은 없다 |
| 회원 | 비회원 기능, 구매 번호 등록과 취소, 내 기록과 당첨 내역, 알림톡 당첨 알림, 비회원 기록 가져오기, 탈퇴 |
| 관리자·운영자 | 기본 운영 통계, 회차별 알림 발송 현황과 수동 다시 보내기, 정정된 공식 결과 승인. 별도 권한과 다중 요소 인증이 필요하다 |

로그인은 카카오, 구글, 네이버 소셜 계정으로 한다. 비회원 규칙은 [02 7.1](02-policies.md#71-비회원)에 있다.

## 3. 기본 이용 흐름

**추천받아 관리하는 경우**

1. 추천을 요청하면 현재 회차의 5세트를 받는다.
2. 회원은 내 기록에서 추천 번호를 본다.
3. 서비스 밖에서 실제로 구매한다.
4. 구매한 번호를 구매 기록으로 등록한다. 추천받은 번호면 그 기록에 구매 표시만 붙는다.
5. 결과가 나오면 당첨 여부를 확인하고, 알림에 동의한 회원은 알림톡을 받는다.

**이미 산 번호를 확인하는 경우**

1. 회차와 번호를 입력하거나 복권의 QR을 스캔한다.
2. 결과만 볼 때는 로그인하지 않아도 된다. 저장하려면 로그인해 구매 기록으로 등록한다.

구매 사이트를 열거나 번호를 입력했다는 사실만으로 구매 완료로 처리하지 않는다.

## 5. 첫 출시 범위

첫 출시는 **추천 → 구매 등록 → 결과 확인 → 알림 → 기본 운영 통계** 흐름을 완성한다(D-012). 설계 규모는 [04](04-data.md)의 테이블 42개 기준으로 유지한다(D-026).

이 흐름을 성립시키는 기반도 첫 출시에 들어간다. 회원 로그인, 비회원 자격, 본인 내역, 취소·탈퇴, 공식 결과 수집, 접근 통제와 관리자 감사, 중복 방지, 백업·복원, 알림 비용 관리, 운영자 알림이다.

첫 출시에 없는 것: 추천 횟수 제한과 광고(D-001, D-008), 구매 자동 입력(보류), 4절의 후속 기능 화면.

## 6. 보류, 제외, 향후 확장

- **보류.** 구매 사이트 자동 입력(D-009), 개발 자동 실행기(D-006). 사용자가 재개를 지시하기 전에는 조사·설계를 하지 않는다.
- **나중에 도입.** 추천 횟수 제한과 광고 보상. 수치와 광고 제공자는 도입할 때 정한다. 구매 수량 관리도 필요할 때 검토한다.
- **채택하지 않은 후보.** 이전 제안 문서에 있던 운영 도구 후보(한도 보정, 공지 관리 등) 가운데 4절에 없는 것은 범위 밖이다.
- **제외(D-021).** 당첨금 수령 안내와 개인 수령 표시, 개인 기록 내보내기, 이용 예산·쉬어가기.
- **향후 확장(원본 요구사항).** 연금복권 추천과 저장, 번호 분석과 통계 기반 추천, 마이페이지와 개인 추천 통계 차트, 관리자 기능 확장.

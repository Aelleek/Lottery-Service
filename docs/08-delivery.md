## 2. 구현 순서

앞 단계의 오류가 뒤로 퍼지지 않게 순서를 정했다. 번호 저장이 정확한지 모르는 채로 알림부터 붙이면 틀린 기록을 사용자에게 보낼 수 있다.

| 단계 | 작업 | 끝났다고 보는 조건 |
|---|---|---|
| 1 | CI가 테스트를 실제로 돌리게 고침. `Clock` 주입. 번호 값 객체와 오류 형식 | 번호·등수·시간 경계 단위 테스트가 CI에서 돈다. 정적 분석 실패가 CI 실패가 된다 |
| 2 | migration 도입, 제약, MySQL 테스트 환경 | 빈 DB와 기존 표본 DB 이행. 조합 중복, FK, version, rollback 확인 |
| 3 | 계정(제공자 3곳), 비회원 자격과 발급 제한, 세션, 회차 일정, 관리자 권한·감사 기반, job lease 회수 | 이메일 병합 없음. 주체 소유권. 마감·개시·결과 지연이 서로 독립 |

outbox, job, 삭제 기반은 단계 2~3에서 먼저 만들고, 각 기능에 맞춰 검증한다. 개인정보 차단과 집계를 마지막 단계까지 미루지 않는다.

## 3. 테스트 원칙

- 잠금과 유일성은 실제 MySQL로 검증한다. H2에서 통과한 것을 근거로 삼지 않는다.
- 시간 경계는 `Clock`과 DB 시각을 함께 조작해 검증한다.
- 무작위 생성의 균등성은 작은 번호 공간에서 후보 전체와 금지 집합으로 검증하고, 고정 seed로 회귀를 확인한다. 느슨한 빈도 테스트 하나로 균등성을 증명했다고 하지 않는다.
- 외부 연동(결과 API, SOLAPI, Discord, OAuth)은 테스트 대역으로 단위·통합 검증하고, 실제 연동은 출시 조건으로 따로 확인한다.

## 4. 데이터 이행

1. 현재 DB를 읽기 전용으로 조사한다. DB 버전, 시간대, DDL, 번호·회차·회원의 NULL, 중복, 구매 플래그, 이메일 연결 충돌 수를 센다. 개인정보 원문을 작업 로그에 넣지 않는다.
2. 새 테이블에 번호를 정규 형식으로 바꾸고 주인을 연결한다. 같은 회원·회차·조합은 하나로 합치고, 구매 여부는 OR로, 추천 시각은 확인 가능한 가장 이른 값으로 둔다. 옛 행과 새 행의 매핑으로 표본과 수량을 대조한다.
3. 추천 횟수나 주인을 확정할 수 없는 행은 격리한다. 주인 증명이 없는 비회원 기록은 현재 브라우저에 연결하지 않는다. 회차가 1112로 고정돼 실제 회차를 알 수 없는 기록은 추측해서 바꾸지 않는다.
4. 과거 행 수를 5로 나눠 추천 횟수를 만드는 식으로 통계를 만들지 않는다. 옛 자료(`LEGACY_UNKNOWN`)와 새 정확 집계의 시작점을 나눈다. 옛 자료를 알림 대상으로 넣지 않는다.
5. 순서는 번호 정규화 → 충돌 보고 → 확인된 매핑 → 유일성·FK 적용이다. 애매한 행만 보류하고 새 스키마 검증은 계속한다.
6. 전환 때 짧게 쓰기를 멈추고, 마지막 증분을 옮기고, 대조한 뒤 새 읽기·쓰기 경로를 함께 켠다. 처음부터 무기한 이중 쓰기를 만들지 않는다. 옛 테이블은 대조, 복원 연습, 보관 검토가 끝나기 전에는 지우지 않는다.
7. 전환 뒤 새 쓰기가 생겼으면 옛 DB 스냅샷으로 바로 되돌리지 않는다. 새 쓰기를 살리는 전진 수정이나 검증된 역이행으로 대응한다.

| T40 | 한 IP에서 자격 발급 한도 초과 | 429와 다시 시도할 시각. 이미 발급된 자격과 추천에는 영향 없음(통합) |
| T41 | 낙첨 기록의 30일 정리, 같은 요청에 4등 기록 1개 | 자식 테이블 처리 후 삭제 성공. 4등 기록 유지. 집계 불변(MySQL) |
| T42 | Discord 웹훅 실패 | 운영자 알림 재시도. 회원 발송 영향 0(통합) |
| T43 | 첫 게시본으로 낙첨이라 대상 없음으로 끝난 구매 번호가 정정 뒤 4등 / 기본 알림이 기간 만료된 뒤 정정 | 앞은 기본 알림 1건 생성, 뒤는 정정 알림 1건. 둘 다 정정 알림 허용 시간에 발송. 기본 알림은 회원·회차당 1건 유지(통합) |
| T44 | 기본 알림 기한 경과, UNKNOWN 남음 / 정정 알림 다시 보내기 기한 전 / UNKNOWN 종결과 모든 기한 경과 뒤 | 앞은 알림 계획 완료 안 함, 뒤는 완료하고 주기 CLOSED. 그 뒤 낙첨 기록 정리 가능(Clock+MySQL) |
| T45 | job 처리 중 worker 종료, lease 만료 | 회수 worker가 RETRY_WAIT로 돌림. 시도 상한 초과 시 DEAD와 운영자 알림 1건(MySQL) |
| T46 | UNKNOWN이 대조 기간 동안 풀리지 않음, 그 뒤 콜백 도착 | FAILED로 종결, 예산 확정 사용, 운영자 알림. 늦은 콜백으로 재발송 0(Clock+통합) |
| T47 | 결과 API가 회차를 주지 않아 직접 등록, 이후 API가 같은 결과 / 다른 결과 | 등록 즉시 게시·판정·알림. 같으면 확인 표시만, 다르면 격리. 이미 게시된 회차의 직접 등록은 거부(통합) |
| T48 | 로그인 때 가져오기 거절, 3일 뒤 내 기록 화면에서 가져오기 / 비회원 보관 기간 경과 뒤 | 앞은 가져오기 성공, 마감 뒤 회차 안내. 뒤는 가져올 수 없음 안내(통합) |
| T49 | 격리된 결과와 같은 내용이 5분마다 계속 수신 | 격리 행 1개, 운영자 알림 1건(통합) |

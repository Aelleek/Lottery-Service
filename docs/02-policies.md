# 02 정책

첫 출시 서비스 규칙과 수치의 정본이다. 후속 기능의 수치는 [09](09-later-features.md), 운영 목표·경보·일정은 [07](07-operations.md)에 있다. 괄호 안 D-번호는 [10 결정 기록](10-decisions.md)의 ID다.

기간·예산·상한은 대부분 공식 값이 아니라 초기 설정이다. 운영 측정 결과가 나오면 근거를 남기고 조정한다.

## 1. 시간과 회차

- 기준 시간대는 서울(Asia/Seoul)이다. DB에는 UTC로 저장한다.
- 회차 일정은 공식 판매 일정과 회차별 예외를 DB에 등록해 쓴다. 기본 일정은 토요일 20:00 판매 마감, 일요일 06:00 다음 회차 판매 개시다. 추첨 시각도 공식 일정 값을 쓴다.
- 판매 마감부터 다음 회차 개시까지는 **새 추천만** 막는다(D-003). 조회, 결과 확인, 구매 등록은 그대로 된다.
- 이 구간의 기본 내역은 방금 마감한 회차다. 다음 회차가 개시되면 추천과 기본 내역이 함께 새 회차로 바뀐다.
- 평일 심야처럼 판매 시간 밖이어도 같은 회차 안이면 추천은 막지 않는다. 다만 "지금 구매할 수 있다"고 안내하지 않는다.
- 추천을 시작했을 때는 마감 전이었어도, 최종 저장 순간에 마감이 지났으면 저장하지 않는다. 다음 회차로 몰래 바꾸지 않고 회차가 바뀌었다고 안내한다.
- 다음 회차 일정이 등록돼 있지 않으면 회차를 계산으로 만들지 않는다. 추천만 멈추고 조회는 유지한다.
- 결과 수집이 늦어져도 다음 회차 개시는 막지 않는다.

## 2. 추천

### 2.1 기본 규칙

- 추천 1회는 서로 다른 5세트다. 1세트는 1~45 중 서로 다른 숫자 6개다.
- 같은 주체가 같은 회차에 이미 받은 조합은 다시 주지 않는다(D-025). 숫자 순서는 무시한다. 예를 들어 `1·2·3·4·5·6`을 받았다면 같은 조합은 빼고, `1·2·3·4·5·7`은 준다. 다른 사람과 같은 조합이 나오는 것은 괜찮다.
- 비회원 기록을 회원에게 귀속했다면, 그 비회원이 받은 조합도 제외 대상에 합친다.
- 새 조합 5개를 채우지 못하면 실패로 안내하고 아무것도 저장하지 않는다. 일부만 성공으로 주지 않는다.
- 추천 횟수 제한과 광고는 없다(D-001, D-008). 나중에 제한을 붙일 수 있도록 이용 정책을 분리해 둔다. 제한이 없던 기간의 사용량을 나중에 생긴 한도에서 소급해 빼지 않는다.
- 과부하 보호로 주체당 동시 생성 1개, 최소 1초 간격을 둔다. 넘으면 다시 시도할 시각을 안내한다. IP는 추가 과부하 신호로만 쓰고, 같은 공유망 사용자를 한 사람으로 보지 않는다.
- 같은 요청을 다시 보내면 새 추천이 아니라 처음 결과를 돌려준다.

### 2.2 생성 방식

기본 추천은 회원과 비회원에게 같은 방식으로 동작한다(D-028).

1. 1~45에서 서로 다른 6개를 편향 없이 무작위로 뽑는다.
2. 생성 필터 7개를 차례로 적용한다. 하나라도 걸리면 버리고 다시 뽑는다.
3. 이미 받은 조합이면 버리고 다시 뽑는다.
4. 5세트가 모이면 저장한다.

**생성 필터(필터 버전 `FILTER_V1`)**

| 순서 | 필터 | 제외하는 조합 | 예시 |
|---|---|---|---|
| 1 | 과거 1등 | 추천 회차보다 앞선 회차의 게시된 1등 조합과 같은 조합 | — |
| 2 | 끝수 합 | 각 숫자 일의 자리의 합이 14 미만이거나 42 초과 | `10, 20, 30, 40, 41, 42` → 합 3, 제외 |
| 3 | 같은 끝수 | 일의 자리가 같은 숫자가 4개 이상 | `1, 11, 21, 31, 5, 9` → 끝수 1이 4개, 제외 |
| 4 | 저·고 | 1~22를 저, 23~45를 고로 볼 때 6개가 모두 저이거나 모두 고 | `1, 3, 5, 8, 13, 20` → 모두 저, 제외 |
| 5 | 홀·짝 | 6개가 모두 홀수이거나 모두 짝수 | `1, 7, 13, 25, 33, 41` → 모두 홀수, 제외 |
| 6 | 차이 종류 | 두 숫자씩 짝지은 15개 차이 중 서로 다른 값이 6개 이하 | `2, 9, 16, 23, 30, 37` → 차이가 7, 14, 21, 28, 35의 5종류, 제외 |
| 7 | 세 구간 | 1~15, 16~30, 31~45 중 한 구간에 6개가 모두 있음 | `16, 18, 20, 22, 25, 29` → 모두 16~30, 제외 |

예시는 앞 순서의 필터는 모두 통과하고 그 필터에서 처음 걸리는 조합이다.

- 필터 6은 현재 코드의 기준(차이 종류 6개 이하 제외)을 유지한다(D-033). 보통 쓰는 AC값은 차이 종류 수에서 5를 뺀 값이라 이름(`ArithmeticComplexityMax6`)과 계산이 다르지만, 이를 알고 정한 것이다. 무작위 조합의 약 0.02%만 걸러 낸다. 서비스가 완성된 뒤 검증 결과를 보고 기준을 바꿀 수 있고, 바꾸면 필터 버전을 올린다.
- 필터는 당첨 확률을 높이지 않는다. 추천 화면에 이 취지의 안내를 둔다. 문구는 아직 정하지 않았다.
- 추천 요청마다 생성 방식과 필터 버전을 기록한다. 필터를 바꾸면 버전을 올린다.
- 조건 추천에는 필터를 적용하지 않는다(D-028). 사용자가 고른 조건만 지킨다.

### 2.3 조건 추천 입력 범위

조건 추천 화면은 후속 기능(SF-02)이지만, 서버는 첫 출시부터 이 입력을 받을 수 있게 만든다 **[미확인]**. 화면과 흐름은 [09 2.2](09-later-features.md#22-sf-02-조건-추천)에 있다.

- 넣을 번호 0~5개, 뺄 번호 0~39개. 같은 숫자를 양쪽에 넣을 수 없다(D-015).
- 남은 후보 조합 수는 C(45 − 넣을 수 − 뺄 수, 6 − 넣을 수)다. 여기서 이미 받은 조합을 빼고 5개 이상이어야 한다.
- 뺄 번호 상한 39는 **조합이 하나라도 남는** 상한이다. 5세트를 만들 수 있는 실제 상한은 넣을 번호가 0~2개면 38, 3~4개면 37, 5개면 35다. 예를 들어 넣을 번호 없이 39개를 빼면 남는 숫자가 6개라 조합이 1개뿐이고, 요청은 항상 실패한다. 화면에는 남은 후보 수를 보여준다.
- 후보가 부족하면 조건을 몰래 완화하지 않고, 이유를 알려 수정하게 한다.

## 3. 구매 기록

- 회원만 등록한다. 수동 입력과 QR 스캔을 지원한다. QR이 안 되면 수동 입력으로 이어 간다.
- 입력은 회차와 숫자 6개다. 6개, 1~45, 중복 없음을 검사한다.
- 회원·회차·조합당 기록은 하나다. 구매 수량은 저장하지 않는다(D-013).
  - 추천만 받은 조합을 등록하면 새 기록을 만들지 않고 기존 기록에 구매 표시를 붙인다.
  - 이미 구매 등록한 조합이면 "이미 등록된 번호"로 안내하고 기록을 늘리지 않는다.
  - 숫자가 같아도 회차가 다르면 다른 기록이다.
- 한 요청에 한 회차, 최대 100세트까지 등록한다. 회차 전체 누적 한도는 아니다. 여러 번 나눠 계속 등록할 수 있다.
- 결과가 나온 뒤에도 등록할 수 있다. 늦게 등록한 번호는 웹에서 판정하지만 기본 알림을 새로 보내지 않는다.
- 기록 수를 실제 복권 장수로 표시하지 않는다. 금액은 공식 자료의 1게임 기준으로만 표시한다.

**취소와 삭제(D-004)**

| 기록 | 사용자가 할 수 있는 일 | 결과 |
|---|---|---|
| 추천받은 뒤 구매 등록한 기록 | 구매 등록 취소 | 구매 표시만 해제. 추천 기록은 남고 추천 보관 기간을 따른다 |
| 직접 입력·QR로 만든 기록 | 기록 삭제 | 내역에서 사라진다 |
| 추천만 받은 기록 | 없음 | 개별 삭제를 제공하지 않는다 |

취소나 삭제를 해도 이미 집계한 생성량과 같은 회차의 추천 이력은 그대로다. 구매 상태를 바꿨다는 이유로 알림을 보내지 않는다.

## 4. 내역 조회

- 기본 화면은 이번 회차의 본인 기록을 10개씩 보여준다. 이번 회차는 판매 중인 회차이고, 마감 구간에는 방금 마감한 회차다.
- 추천만 받은 번호와 구매한 번호를 구분해 보여준다. 지난 회차의 기록과 당첨 여부도 볼 수 있다.
- 이번 회차 기록이 0건이면 추천 화면으로 보낸다. 이동만으로 번호를 만들지 않는다. 마감 구간이면 "이번 회차 추천 마감", 다음 개시 시각, 결과 확인과 구매 등록 경로를 보여준다.
- 사용자가 과거 회차를 직접 고른 조회나 필터 결과가 0건이면 이동하지 않는다.
- 조회 실패를 0건으로 표시하지 않는다.
- 비회원도 보존 중인 본인 추천을 같은 회차 규칙으로 조회한다.

## 5. 결과와 판정

- 결과 수집, 등수 판정, 금액 표시를 나눈다(D-037). 번호와 보너스가 검증되면 금액이 없어도 등수부터 보여주고 금액은 "확인 중"으로 둔다.
- 미발표, 수집 실패, 판정 대기, 낙첨을 구분한다. 판정 전 기록은 "확인 중"이고 낙첨으로 보이지 않는다.
- 등수: 1등 6개 일치, 2등 5개와 보너스, 3등 5개, 4등 4개, 5등 3개. 보너스는 2등 판단에만 쓰고 일치 개수에 더하지 않는다.
- 이미 게시한 결과와 다른 공식 결과가 오면 바로 바꾸지 않고 격리한다. 운영자가 사유와 함께 승인해야 새 게시본이 된다. 이미 격리한 결과와 같은 내용이 다시 오면 새로 격리하거나 알리지 않는다.
- 결과 API가 회차 결과를 주지 않으면 ADMIN이 공식 발표를 보고 결과를 직접 등록할 수 있다(D-034). 사유, 최근 5분 안의 재인증, 감사 기록이 필요하다.
  - 그 회차에 게시된 결과가 없고 추첨 시각이 지났을 때만 등록할 수 있다. 이미 게시된 결과를 고치는 데는 쓰지 않는다 **[미확인]**.
  - 화면은 번호와 보너스를 두 번 입력받아 같을 때만 제출한다 **[미확인]**.
  - 등록한 결과는 API로 받은 결과와 똑같이 게시·판정·알림에 쓰인다. 등수별 금액은 받지 않는다. 결과 API가 나중에 주면 채우고, 그 전까지는 "확인 중"이다.
  - 나중에 결과 API가 같은 결과를 주면 확인 표시만 남긴다. 다른 결과를 주면 일반 정정과 같이 격리하고 승인을 받는다.
- 즉시 확인: 회원·비회원 모두 회차와 번호(최대 5세트)를 입력하거나 QR로 확인한다. 저장하지 않는다.

## 6. 당첨 알림

### 6.1 대상과 묶음

- 채널은 카카오 알림톡 하나다. SMS와 실패 시 문자 대체 발송은 없다(D-005). 발송 제공자는 SOLAPI다.
- 대상: 구매 등록한 번호는 1~5등, 구매 등록하지 않은 추천 번호는 1~3등이다. 비회원에게는 외부 알림이 없다.
- 대상 기준 시점은 판매 마감이다. 마감 시점에 저장돼 있던 기록과 구매 상태로 대상을 고정한다. 결과가 늦어져도 기준 시점을 뒤로 옮기지 않는다.
- 보내기 직전에 현재 소유, 동의, 구매 상태를 다시 확인한다. 예를 들어 마감 때 구매 등록이었던 4등 번호를 발송 전에 취소했다면 보내지 않는다.
- 회원당 회차별 기본 알림은 1건이다. 요약과 로그인이 필요한 상세 링크로 보낸다. 번호가 많아도 여러 건으로 나누지 않는다. 대상이 없으면 보내지 않고 "대상 없음"으로 완료 처리한다.
- 늦게 등록하거나 구매 상태를 바꿨다는 이유로 추가로 보내지 않는다.
- 등수별 금액이 아직 없어도 기다리지 않고 보낸다. 금액은 "확인 중"으로 안내한다.
- 추천 번호 알림은 "추천받은 번호가 N등 번호와 일치했다"고 쓴다. 실제 구매나 당첨금 수령 권리를 단정하지 않는다.

### 6.2 발송 시각과 재시도

결과 알림은 정해진 발송 슬롯에만 보낸다(D-027). 슬롯 시각은 추첨일 기준이다.

| 슬롯 | 동작 | 실패 시 운영자 알림 |
|---|---|---|
| 추첨일 21:30 | 결과를 확인하고 알림을 보낸다 | 보낸다(원인 포함) |
| 추첨일 22:00, 22:30, 23:00 | 아직 못 받은 회원에게 다시 시도한다 | 보내지 않는다 |
| 추첨일 23:30 | 다시 시도한다. 그날 마지막 슬롯이다 | 보낸다 |
| 다음 날 09:00 | 다시 시도한다 | 보낸다 |
| 다음 날 09:30~11:30(30분 간격) | 다시 시도한다 | 보내지 않는다 |
| 다음 날 12:00 | 마지막으로 시도한다. 실패하면 자동 발송을 끝낸다 | 보낸다 |

- 슬롯의 "실패"는 두 경우다. 그 시각까지 결과를 게시하지 못한 경우(아직 미발표이거나 결과 API를 읽지 못함), 그리고 결과는 있지만 일부라도 발송이 실패한 경우다.
- 다시 시도할 때는 아직 못 받은 회원에게만 보낸다. 이미 접수된 회원에게 다시 보내지 않는다.
- 제공자 접수 여부를 모르는 메시지(UNKNOWN)는 다음 슬롯에 다시 보내지 않고 대조한다. 마지막 슬롯까지 풀리지 않으면 마지막 운영자 알림에 건수를 넣는다.
- UNKNOWN이 된 뒤 7일 동안 대조해도 확정하지 못하면 FAILED로 끝내고, 비용은 쓴 것으로 본다. 운영자에게 알린다 **[미확인]**.
- 슬롯 시작 후 10분 안에 대상 전원의 제공자 접수를 마치는 것이 목표다 **[미확인]**. 실제 수신 보장은 아니다.
- 결과 수집은 슬롯과 별도로 추첨이 끝난 뒤부터 진행한다. 화면에는 게시되는 즉시 결과가 보인다. 수집 일정은 [07 1](07-operations.md#1-작업-일정)에 있다.
- 다음 날 12:00 뒤에는 자동으로 보내지 않는다. 남은 알림은 운영자가 원인을 고친 뒤 관리자 화면의 "다시 보내기"로 보낸다(D-031). 이미 받은 회원과 접수 확인 중인 회원은 빠진다. 기본 알림의 다시 보내기는 결과 게시 후 7일 안에서만 할 수 있다 **[미확인]**. 정정 알림의 기한은 6.3에 있다.
- 7일이 지나도록 못 보낸 알림은 "미발송·기간 만료"로 표시한다. 결과 조회는 그대로 된다.
- 운영자 알림은 Discord로 보낸다(D-030). 내용과 규칙은 [07 2](07-operations.md#2-운영자-알림)에 있다.

### 6.3 정정 알림

- 이미 안내한 내용이 공식 결과 정정으로 틀려졌을 때 보낸다. 안내한 등수가 바뀌었거나, 안내한 금액이 틀렸을 때다. 낙첨이나 알림 대상 밖 등수로 바뀐 경우도 포함한다.
- 안내를 받지 않은 마감 대상 기록이 정정으로 알림 대상 등수(6.1)가 된 경우에도 보낸다. 예를 들어 첫 결과로는 낙첨이라 알리지 않은 구매 번호가 정정 뒤 4등이 된 경우, 또는 기본 알림이 기간 만료로 끝내 가지 못한 뒤 정정된 경우다. 그 회원의 기본 알림이 아직 없으면 이것이 기본 알림이 되고, 있으면 정정 알림이 된다. 어느 쪽이든 발송 시간은 이 절을 따른다 **[미확인]**.
- 금액을 "확인 중"으로 안내했다가 금액이 확정된 경우는 정정이 아니다. 화면만 갱신한다.
- 정정 알림은 요일과 관계없이 09:00~23:30에만 보낸다. 이 시간 밖에 정정이 확인되면 다음 09:00에 보낸다(D-032).
- 실패하면 허용 시간 안에서 30분마다 다시 시도한다. 유효기간은 정정 확정 후 7일이다 **[미확인]**.
- 유효기간이 지나 만료된 정정 알림도 운영자가 "다시 보내기"로 보낼 수 있다. 정정 확정 후 14일 안에서만 된다 **[미확인]**.
- 기본 알림이 아직 접수 확인 중이면, 그 상태를 먼저 대조한 뒤 정정 여부를 판단한다.

### 6.4 수신 번호와 동의

- 회원이 직접 입력한 전화번호로 인증용 알림톡 코드를 보낸다. 6자리, 5분 유효, 오답 5회까지, 재발급 간격 60초, 번호별·계정별 하루 5회다.
- 인증을 마친 번호에만 수신 동의를 받는다. 번호를 바꾸면 이전 동의를 끄고, 새 번호를 인증하고, 다시 동의받는다. 동의를 철회하면 새 발송을 즉시 막는다.
- 인증 코드는 사용자가 요청한 것이므로 발송 슬롯과 관계없이 바로 보낸다.
- 카카오톡을 쓰지 않거나 차단했거나 받지 못하면 외부 알림만 보류된다. 웹 결과 확인은 그대로 된다.

### 6.5 비용

- 월 메시지 예산은 30,000원(VAT 포함)이고 자동 충전은 없다. 알림톡 13원/건(VAT 별도) 기준 약 2,097건이다.
- 예산의 20%는 정정 알림, 10%는 인증 코드용으로 남겨 두고 나머지를 기본 알림에 쓴다.
- 예산에 막히면 추가 과금 없이 대기하고 운영자에게 알린다. 유효기간 안에서 예산이 복구되면 보낸다.
- 예산은 설정값이다. 복구는 두 가지다. 다음 달로 넘어가거나, 운영자가 설정을 바꿔 다시 시작하는 것이다. 관리자 화면에서 바로 늘리는 기능은 없다 **[미확인]**. 그래서 월말 회차는 예산 때문에 일부 알림을 끝내 못 보낼 수 있다.
- 기본·정정·인증 템플릿 3종이 카카오 심사를 통과하기 전에는 보내지 않는다.

## 7. 비회원과 계정

### 7.1 비회원

- 서버가 무작위 익명 자격을 쿠키(Secure, HttpOnly, SameSite)로 발급한다. 유효기간은 발급 후 37일이다. 자격을 새로 바꿔도 같은 주체로 이어진다(D-002).
- 쿠키를 지웠거나 다른 기기에서 접속하면 같은 사람으로 확인해 주지 않는다. IP나 기기 정보로 기록 주인을 되찾지 않는다.
- 비회원은 추천과 즉시 확인을 쓸 수 있다. 추천 기록은 추첨일+30일까지만 남는다. 화면에 이 기한과 쿠키 유실 한계를 알린다.
- 자격을 지나치게 많이 발급받는 것을 막기 위해 IP별 발급 속도를 제한한다. IP당 10분에 200회다(D-035). 학교나 회사처럼 여럿이 같은 IP를 쓰는 경우를 고려한 값이다. 제한에 걸리면 화면에 다시 시도할 수 있는 시각을 보여 준다. 추천 횟수 제한이 아니라 자격 발급 제한이다.
- 로그인하면 "이 브라우저의 추천 번호 가져오기"를 묻는다. 거절해도 로그인은 성공한다. 가져오기에 실패해도 로그인은 막지 않는다.
- 거절했거나 중간에 실패한 기록은 나중에 내 기록 화면에서 다시 가져올 수 있다(D-036). 가져오기 전까지는 비회원 보관 기간(8절)을 따르고, 기간이 지나면 가져올 수 없다. 화면에 그 기한을 보여 준다.
- 판매 마감 뒤에 가져온 기록은 그 회차의 알림톡 대상이 아니다(6.1). 가져오기 화면과 결과에 이 사실과 해당 회차를 알린다. 판매 마감 뒤에 구매 등록한 경우도 등록 결과로 같은 안내를 한다.
- 한 비회원 자격의 자료는 한 계정에만 귀속된다. 이미 다른 계정에 귀속된 자료는 보여주지 않는다.
- 가져온 기록 중 같은 조합은 하나로 합치고 출처와 생성 시각을 유지한다. 사용자가 이미 지운 기록은 되살리지 않는다. 구매 표시는 로그인 뒤 직접 등록해야 붙는다.

### 7.2 회원 계정

- 제공자와 제공자 사용자 ID로 계정을 구분한다. 이메일이 같아도 자동으로 합치지 않는다(D-007).
- 로그인에 성공하면 마지막 로그인 시각을 그 시각으로 바꾼다. 관리자가 회원의 마지막 로그인을 확인하거나 오래 접속하지 않은 회원을 찾을 때 쓸 값이다. 이 값을 쓰는 화면은 아직 설계하지 않았다(D-038). 로그인만으로는 통계의 활동으로 세지 않는다([9](#9-통계)).
- 다른 소셜 계정을 연결하려면 현재 계정을 다시 인증하고 새 제공자 인증까지 마쳐야 한다. 이미 다른 회원에 연결된 소셜 계정은 연결할 수 없다. 마지막 남은 로그인 수단은 해제할 수 없다.
- 계정 연결, 연락처 변경, 탈퇴, 다른 기기 로그아웃은 최근 5분 안에 소셜 재인증을 해야 한다. 같은 브라우저의 일반 로그아웃은 바로 된다.
- 세션은 기본적으로 브라우저 세션이다. "로그인 유지"를 고르면 최대 30일, 14일 동안 쓰지 않으면 만료된다. 로그아웃과 탈퇴는 서버에서 즉시 세션을 회수한다.
- 관리자 계정은 로그인 유지가 없다. 30분 미사용 또는 최대 8시간이면 만료되고, 다중 요소 인증을 쓴다.

### 7.3 탈퇴와 재가입

- 탈퇴하면 접근, 세션, 발송을 즉시 막는다. 개인 자료는 24시간 안에 지운다. 개인을 식별하지 않는 서비스 통계는 남긴다(D-024).
- 이미 상대에게 전달된 메시지는 회수했다고 말하지 않는다.
- 같은 소셜 계정으로 다시 가입하면 새 회원으로 받는다. 탈퇴 전 기록은 복구하지 않는다(D-029).

## 9. 통계

첫 출시는 기본 지표만 제공한다(D-011). 관리자 실험 화면과 차트 확장은 후속이다.

- 날짜는 서울 00:00~24:00이다.
- 활동은 추천 성공, 구매 등록, 본인 기록·결과 조회, 즉시 확인 중 하나의 성공으로 정의한다.
- 첫 화면 지표: 신규·활성 회원, 익명 브라우저 활동 수, 추천 시도·성공·실패와 생성 세트 수, 구매 등록 조합 수, 판정 완료·대기와 등수별 건수, 알림 상태와 비용, 결과 수집과 작업 지연.
- 생성 세트 수는 추천이 성공한 시점 기준이다. 기록을 합치거나 지우거나 가져와도 늘거나 줄지 않는다.
- 일별 고유 이용자를 더해 월별 고유 이용자로 쓰지 않는다. 익명 브라우저 수를 실제 사람 수로 표시하지 않고, 회원 수와 더하지 않는다.
- 당첨 비율의 분모는 판정 완료 수다. 미판정 수는 따로 보여준다.
- 서울 기준 월 마감 후 7일 동안 늦게 들어온 자료를 보정한다. 그 뒤의 늦은 자료는 집계 버전과 시각으로 표시한다.
- 통계 숫자를 직접 고치는 기능은 없다. 원천과 대조해 감사 기록을 남기는 재집계로만 고친다.
- 관리자 실험 번호는 사용자 통계에 섞지 않는다.
